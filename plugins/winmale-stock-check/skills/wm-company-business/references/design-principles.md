# 设计原则与要点（生意解读卡）

本卡 = Insight `company_snapshot` 的 **SkillHub 事实孪生**：XS 出可对账事实，Agent 按 Pack 写三问解读。不做估值裁决（匹配见估值卡）。

> **完整设计母本**（跨卡可复用骨架 + 本样板细节）：仓库 [`docs/CAPABILITY_CARD_DESIGN.md`](../../../docs/CAPABILITY_CARD_DESIGN.md)。本文是 Agent 侧短摘要。

## 分层（硬）

| 层 | 负责 | 不负责 |
|----|------|--------|
| **XS / Data+Gate** | 取数、口径、金融剥离、HK 金融拦截、`methodology` / `enrich_plan` / `quality` | 写解读正文 |
| **Pack / Narrative** | 透镜、指令、输出骨架、Verify | 改数字、编造对照、改 `enrich_plan` |

一次 `skills/run` 拿齐事实面；解读只在宿主 LLM 侧按 `enrich_plan.required_reads` 生成。

## 五原则（高于篇幅）

**专业 · 买方视角 · 准确 · 简洁 · 易懂**

冲突序：**准确 > 简洁 > 填满**；专业/买方 > 文采。

| 原则 | 落点 |
|------|------|
| 专业 | 买方口径；禁荐股/营销腔；分位与增速只报事实 |
| 买方 | 解读回答「对仓位意味着什么事实」；定价只定位 |
| 准确 | 数字照抄 JSON；禁无依据 `≈`、禁心算派生、禁编造行业对照 |
| 简洁 | 每章解读 2～4 短句；缺字段不写；不为表而表 |
| 易懂 | 术语括注；表头语义清楚；禁内部字段名 |

## 读者三问（结构）

1. **生意基因** — 这门生意怎么赚钱（模式 + 回报/结构事实）
2. **核心矛盾** — 当下最大张力（增速、偿债、现金流画像）
3. **定价位置** — 市场给什么价（PE/PB 与分位事实；低分位≠低估）

头区散文：标题、商业模式、30 秒、核心观点 3 条 → 再进三章。

## 输出形态（对照表-only）

表格**只**服务「本公司 vs 行业」同口径并读；其余进散文。

| 规则 | 说明 |
|------|------|
| 出表条件 | 本章 ≥2 行双侧同口径 → 至多一张 `与行业对照`（`指标 \| 本公司 \| 行业`） |
| 零表 | 不足 2 行 / 无行业 → 该章零表，数字写解读 |
| 禁碎表 | 禁止「本公司指标」两列表、禁止 `—` 凑列、禁止旧表头「对照/分位」 |
| 行业列 | 一个主数字；分位用括号短注或解读句 |
| 口径 | TTM 同比 ≠ 近3年年化；不一致勿强行对照 |
| 现金流类型 | **永不入表**；解读用类型短名一句；禁展开投资科目 |
| 估值 | 默认散文；可选一张 `指标 \| 数值 \| 五年分位` |
| 禁止 | 「维度｜数据｜解读」三列表（解读不准塞进表） |

稀疏/港股缺对照时，**无表优于碎表**。

## Gate 与卫生

- **CN 金融**：剥净现比 / 八型 / 有息负债等工业指标；换金融 instruction + lens
- **HK 金融**：请求层 `blocked`，只出 `blocked_message`
- **分部占比**：只用返回的 `top_share`；无则禁写精确 %
- **旗标**：如 `net_interest_income` 只记事实句，不外推

## Agent 工作要点

1. 先 `run`，读 `methodology` / `enrich_plan` / `quality`；`blocked` 则停
2. **禁止改** `enrich_plan`；Read 完 `required_reads`，勿读 `do_not_load`
3. 按 `output-skeleton` 起草；数字对账；透镜禁行业套话串味（尤其勿把茅台叙事套到低毛利高周转）
4. `verify-checklist` 内部自检至 G1=0；最多回退 2 次（**勿向用户口述**）
5. **交付静默**：对用户只输出 skeleton 终稿；禁止 W 阶段旁白、`G1=`、流程回顾、终稿合格口播
6. 字数软区间约 700～1400 汉字；不承诺每次合格，但不合格可检测
7. 勿与 `wm-company-card` 混淆；勿默认调 `/v1/insight/report`
